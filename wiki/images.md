# Images

Originals go into a private R2 bucket. Visitors only ever get resized derivatives from `/img`. The spec, including the size table, is [DESIGN.md → Image storage & delivery](../docs/DESIGN.md#image-storage--delivery). In code, the source of truth for sizes, quality and watermarking is `SIZE_SPECS` in [src/lib/images.ts](../src/lib/images.ts).

## Originals in R2

- **Key:** `originals/<photoId>/v<version>.<jpg|png|webp>` (`originalKey`).
- **Upload:** `PUT /api/admin/photos/:id/original` → `storeOriginal` in [src/lib/originals.ts](../src/lib/originals.ts):
  1. `Content-Type` must be JPEG, PNG or WebP, else 415. `Content-Length` must be ≤ 100 MB, else 413.
  2. The body streams into R2. It's buffered only when the client sent no `Content-Length`.
  3. The stored object goes through `env.IMAGES.info()`. The format must match `Content-Type`, and SVG is rejected. If it's not an image, the object is deleted and the response is 415.
  4. Dimensions come from `reconcileDimensions` ([originals-pure.ts](../src/lib/originals-pure.ts)). It combines the binding's pixel grid with the browser's display size and the `X-Exif-Orientation` header.
  5. `markPhotoReady` stores the verified mime, bytes and dimensions and sets `status = 'ready'`.
  - If `info()` fails for any other reason: production deletes the object and returns 502. Local dev keeps the browser's numbers and returns `unverified: true`.
- **Replace** (`PUT …/replace`): writes `v<version + 1>`, updates the row (`setPhotoOriginal`), then deletes the old object. The version is part of every image URL, so this busts all caches.
- **Delete:** removes every object under `originals/<id>/` (all versions), then the rows.

## Public route: `GET /img/:id/v:version/:size`

[src/pages/img/[id]/[version]/[size].ts](../src/pages/img/%5Bid%5D/%5Bversion%5D/%5Bsize%5D.ts), in order:

1. **Parse.** The size must be exactly an allowlisted number (`parseSize`: `"480"`, not `"0480"`). The version must be `v` plus a positive integer (`parseVersion`). The id must be a well-formed ULID. Anything else is a 404 without touching D1.
2. **D1 lookup on every request**, before the cache (`getImageSource`). The photo must be ready, published, and on the URL's version. That's why unpublishing or deleting stops a photo serving at once, even when its bytes are cached.
3. **Format:** AVIF if `Accept` includes `image/avif`, else WebP (`pickFormat`). Two formats only.
4. **Edge cache:** `caches.default`, keyed `https://img-cache.internal/<id>/v<version>/<size>.<avif|webp>` (`cacheKey`).
5. **On a miss:** R2 get, then `transformOriginal`. That resizes with `fit: 'scale-down'` (never upscales), draws the watermark when the size calls for one and `photos.watermark = 1`, and encodes at the size's quality. No metadata is copied.
6. **Headers:** `PUBLIC_IMAGE_HEADERS` (`public, max-age=31536000, immutable`, `Vary: Accept`, `inline`). The cache write runs in `waitUntil`.

Failures:
- Error 9422 (monthly transformations used up) → 503 with `Retry-After: 3600`. It's logged, and the original is never served instead.
- Any other transform failure → 503 in production. Local dev serves the original bytes with `no-store`.

**Don't:** serve an original in production, add a size outside `SIZES` casually, or let the route answer for a photo that isn't published. Each (photo, size, format) is one unique transformation a month; the free plan allows 5,000.

## Which sizes go where

- Tiles use 480 / 768 / 1080 (`GRID_SIZES`), the lightbox 1600 / 2400 (`LIGHTBOX_SIZES`), Open Graph 1600.
- The watermark is on 1600 and up.
- `tileSources` / `lightboxSources` in [src/lib/gallery.ts](../src/lib/gallery.ts) build `srcset` entries with the right dimensions. They list a size only once when the original is smaller than several sizes.

## Watermark

- [public/watermark.png](../public/watermark.png) is generated by `pnpm watermark ["© Name"]` ([scripts/make-watermark.mjs](../scripts/make-watermark.mjs), sharp rendering SVG text). Changing the text means regenerating the PNG; `settings.watermark_text` is not read.
- It's drawn bottom-right at 18% of the output's long edge, with a 2% margin and opacity 0.6.
- The route reads the PNG through the `ASSETS` binding once per isolate, with a plain `fetch` as fallback.

## Admin preview: `GET /api/admin/img/:id/:size`

The same transform, but with no publish or version check, no watermark, and `Cache-Control: private, no-store`. Admin islands use it for drafts and thumbnails (`adminImageUrl` in `src/lib/client/http.ts`).

## Local dev differences

- The local Images binding (miniflare + sharp) only rotates, resizes and encodes. It ignores `draw()` and `quality`, so **there's no watermark locally**. To check the real watermark, see [testing.md](testing.md).
- The local binding reports a non-image as error 9523, "unsupported image format"; production uses 9412. Both mean 415.
